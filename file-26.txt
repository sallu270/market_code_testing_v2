
Use `full` initially because the dashboard can show additional market fields.
Actual fields depend on the instrument and the current Upstox feed response.

## Security

- Never commit `.env`.
- Never expose the Flask server directly to the public internet.
- Never put the access token in HTML or browser JavaScript.
- Revoke a token immediately if it is exposed.
- Use a dedicated secure backend before adding order placement.
- Phase 1 must remain data-only until storage and signals are validated.

## Troubleshooting

### Configuration required

The `.env` file is missing, uses the wrong name, or still contains example
values.

### Authentication or connection error

The access token may be invalid or expired. Complete the current Upstox
authorisation flow again and update `.env`.

### Connected but no ticks

Check:

- The instrument key is valid.
- The selected market is currently producing data.
- The instrument key uses the exact Upstox format.
- The configured feed mode is available for the subscription.
- Your account and app have current market-data permission.

### Chart is empty

The chart needs at least one stored one-minute candle for the selected
instrument. Check the raw tick table first.

### Bid and ask are empty

Index feeds may not provide order-book depth. Subscribe to a tradable futures
or options contract using `full` mode.

### Database is locked

Only run one collector instance against the same database file. Stop duplicate
processes before restarting.

## Stop the application

Press `Ctrl+C` in the terminal. The collector disconnects the feed and closes
the SQLite connection.

## Phase 1 boundary

This version intentionally excludes:

- positive and negative signal rules;
- simulated CE or PE orders;
- live order placement;
- stop-loss and daily-loss controls;
- the 3:15 PM square-off engine.

Those features should consume only completed candles after the collector is
stable.
